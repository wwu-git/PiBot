# 6 · 群聊

把几个 Bot 拉进一个群，由一个**统筹**分派工作：被 @ 的 Bot 直接回答，其余消息由统筹接手，必要时拆成计划交给成员。群聊更费用量（每条消息可能由几个 Bot 分别处理），大多数事情和单个 Bot 聊就够了。

## 新建群聊

1. 点左侧栏顶部的「＋」›「新建群聊」（⌘2 / Ctrl+2）。
2. 选一个**群聊模板**，或者自己挑成员：
   - 模板：内容增长组、轻量开发组、产品研发组、研究小组、学习小组，每张卡片写着适合做什么。轻量开发组和研究小组随安装包提供，其余模板第一次用时从角色库下载（需要联网）。选模板会先预览，点「建好群和成员 Bot」后新建模板里的 Bot（用默认模型和角色权限）和群；已经有同一角色的 Bot 会直接拉进群，不再新建。建好后统筹发一条欢迎消息。
   - 自己挑：选 2 到 6 个 Bot。图片 Bot 可以当成员，统筹必须是文本 Bot。
3. 填**群名**，选**统筹**。
4. 点「创建群聊」。

![新建群聊](../images/zh/group-new.png)

群聊也有自己的工作文件夹，默认是「群自己的目录」。在聊天顶部点文件夹名可以换成你的项目文件夹（只有主文件夹可写，只读参考只能读取）：

![群的文件夹](../images/zh/group-folder.png)

## 在群里派活

- 直接说要做什么，统筹会决定谁来做；也可以 @ 某个成员让它直接回答。
- 群聊同样有「执行 / 只规划」。先用「只规划」让大家分析，满意后点「改成执行」再做。
- 群会自己往下推进：统筹拆好任务后，实现、测试、审查依次接力，不用你一步步追问。测试或审查没通过，程序会把问题派回去修，修好后交回同一个角色复验；群里的总结按测试和审查的结论写。
- 群聊顶部显示「自动来回 N / M 次」：Bot 之间互相回复到上限后会停下来等你，你发新消息后重新计数。旁边的「暂停自动对话」开关和下面的「暂停」是同一个操作（见 [暂停与继续](#暂停与继续)）。
- 每个成员的运行都能单独停止（「停止 … 的这次运行」）。

![群聊](../images/zh/group-chat.png)

## 任务面板与计划

点群聊顶部的「任务」打开任务面板：

![任务面板](../images/zh/group-tasks.png)

- **当前计划**：按时间线列出每一步由谁做、要做什么、交付物和检查项，可以同时做的步骤标在一起；下面的「进度」显示每一步进行中、等待中、等你处理、已通过还是未通过，以及已经花了多少。
- **主任务**和**子任务**：谁在做什么，进行中还是等你确认。
- **已结束的任务**。
- **这次用了多少**：本轮所有运行合计的工具次数、模型请求、运行时间和费用（厂商没给价格时说明有几次请求价格未知）。
- **群计划记录**：历次执行计划。

复杂任务时统筹会先给出一张**执行计划**卡片：每一步由谁做、依赖哪些步骤、哪些可以同时进行、交付物是什么，以及预估花费。点「开始」执行，或点「修改」说明要调整的内容，再交给统筹重新规划。

串行步骤在群的主目录里做。可以同时做的开发步骤：在 macOS 上各自用一个独立工作区，完成后经审阅和权限审批再合入群的文件夹；在 Windows 和 Linux 上，以及电脑上还没装 Git 时，这些步骤改为在群的文件夹里轮流做，结果一样，只是慢一些（Git 见 [4 · 工作文件夹与改动](04-folders-and-changes.md#git)）。

一次全部步骤都通过的计划，可以在它的完成消息上「保存为常用计划」，下次直接运行。

## 暂停与继续

群在干活时，输入框上方有一条状态条，显示正在做第几步、谁在做（例如「计划进行中 · 第 2/4 步 · 小栈：…」），右边是「暂停」按钮。

[![群组暂停与继续（点开看视频）](../../assets/pibot-group-pause.gif)](../../assets/pibot-group-pause.mp4)

- **暂停**：正在做的步骤停下来，进度保留，状态条变成「已暂停 · 进度保留，第 N 步「…」停在这里」。步骤里正在跑的命令会被停止；后台运行的服务（比如本地预览）不受影响，继续运行。
- **继续**：点「继续」，被停下的步骤从停下的地方接着做。接着做的 Bot 会知道暂停前它改了哪些文件、跑过哪些命令（被打断的那条标为「被暂停打断」），以及暂停期间有哪些文件被别人（比如你）改过，并重新运行被打断的命令；已经做完的部分不会重做。继续通知会列出这次恢复的每个步骤。
- **状态**：「已暂停」表示这一步可以用「继续」恢复。「已停止」表示计划已被停止或取消。
- **用聊天说**：直接发「先停一下」「暂停」或「接着做吧」「继续」也行，效果和点按钮一样。只有整条消息就是这个意思时才算；带问题或别的要求的消息照常交给统筹。
- **暂停时照常聊天**：可以问成员问题、自己改文件，Bot 只在你发消息或 @ 它时回答。暂停期间新的计划不会开始。
- 聊天顶部的「暂停自动对话」开关和手机上的「暂停 / 继续」是同一个暂停（见 [11 · 手机 App](11-phone-app.md#对话任务和审批)）。

## 群资料与设置

点群名打开群资料面板，有群资料、话题、技能、权限、群设置五个标签。

![群资料](../images/zh/group-info.png)

- **群名**、**统筹**、**自动来回上限**、**群公告**（离开输入框时保存）。改群名不会打断正在做的步骤。
- **成员**：查看成员、加入新的 Bot。成员的私聊不受影响。
- **用过的文件夹**、**运行上限（含费用上限）**。
- **技能**：群可以有自己独立的技能清单。
- **权限**：群有独立的权限范围，只会收紧，不会放宽成员的权限。
- **归档**：停止群的任务，保留聊天和文件；可以在侧栏的「已归档」里恢复。

## 实例：研究员交接给写作 Bot

1. 新建一个包含统筹、研究员和写作 Bot 的群，设好用于交付的工作文件夹。
2. 先选「只规划」，在主群写：「研究员把三份资料的结论和出处记到 research.md。写作 Bot 根据它写 draft.md。先列计划，写作依赖研究完成。」
3. 核对计划卡上的成员、依赖和两个交付物路径，再点「开始」。在顶部「任务」面板跟进每一步。
4. 研究完成后打开 research.md 检查出处。如果写作步骤还在等，先看研究步骤是不是正在等待检查或确认。
5. 初稿完成后在主群打开 draft.md。需要补资料时，在主群引用相关结果再说明缺了什么。
