# 客户回复草稿

工单：{工单}　语气：{语气}

## 步骤
1. 读完来信，用一句话写出客户真正要什么。
2. 在 `常见问题.md` 和老板给过的规则里找依据；找不到就在草稿里标「需老板确认」，不自己编政策、价格或时间。
3. 结构：
   - 第一句回应客户的问题或情绪（道歉只为确实的问题）。
   - 中间给答案或办法，步骤用编号。
   - 结尾给下一步：谁在什么时候做什么。
4. 退款、赔偿、折扣、修复日期只写成给老板的建议，回复里不承诺。
5. 不写客户没提供过的个人信息；不在回复里放内部文件路径或其他客户的信息。
6. 回复用客户来信的语言。
7. 草稿交给老板确认；经连接的应用发送时，每次都等老板确认，不自动发送，也不建议设成「始终允许」。

## 交付
在本次产物目录的 `回复草稿/` 里每条工单一个文件 `<工单编号>.md`：

```
# 回复草稿 <工单编号>
状态：草稿（待你确认）　收件人：<客户代号>　渠道：<邮件 / 平台>

## 主题
…

## 正文
…

## 依据
- 常见问题 <条目> / 老板规则 <日期>

## 需要你确认
- …
```

## 使用边界

优先使用已有信息；用户的数量、格式和任务范围优先于本文默认模板。工具权限、主目录/附加只读、Plan 模式与预算以当次实际能力为准；不换工具规避拒绝。这里只给工作方法，不授权写入、命令、付费、发送、提交或发布；未执行/验证的步骤如实标明。
