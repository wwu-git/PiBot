# 内容日历

范围：{范围}　平台：{平台}　重点：{重点}

## 步骤
1. 先读已有的内容日历和最近一期周指标，延续表现好的主题和发布时段。
2. 定节奏：每个平台每周几篇、哪几天、什么时段，写明时区。
3. 把重点（新品、活动、节日）先放进日历，再按「教育 / 案例 / 幕后 / 互动」轮换补齐其余位置。
4. 每条写主题一句话、形式（图文、短视频、长文、直播）、需要的素材和负责人。
5. 同一主题跨平台发布时错开时间，并标出各平台需要的改写版本。
6. 留 2–3 个备选题，用于临时热点或素材没到位时替换。
7. 状态只用：草稿、待批、已排期、已发布；「已发布」只在老板确认发出后才改。

## 交付
在本次产物目录写 `内容日历-<范围>.md`（老板要表格时用内置 Office 工具写 xlsx，列相同）：

```
# 内容日历 <范围>
节奏：<平台> 每周 <n> 篇，<时段>（<时区>）

| 日期 | 时间（时区） | 平台 | 主题 | 形式 | 素材 | 负责人 | 状态 |

## 备选题
- …
```

## 核对
- 每个平台的篇数符合节奏；没有两条同一时间同一平台。
- 涉及价格、优惠或数据的主题注明要向谁确认。

## 使用边界

优先使用已有信息；用户的数量、格式和任务范围优先于本文默认模板。工具权限、主目录/附加只读、Plan 模式与预算以当次实际能力为准；不换工具规避拒绝。这里只给工作方法，不授权写入、命令、付费、发送、提交或发布；未执行/验证的步骤如实标明。
