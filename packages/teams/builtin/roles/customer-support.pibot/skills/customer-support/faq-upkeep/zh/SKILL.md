# 常见问题维护

工单：{工单}

## 步骤
1. 先读现有的 `常见问题.md`；没有就新建。
2. 从工单里找出现 2 次以上的问题，以及答错或答得慢的问题。
3. 每条问答：
   - 问题用客户的说法写。
   - 答案先给结论，再给步骤；涉及价格、退款、时限的只用老板给的规则，并注明规则日期。
   - 写适用条件（哪个套餐、哪个版本、哪个地区）。
   - 记来源工单编号和更新日期。
4. 已有条目和新情况冲突时不直接改：写进「待你确认的改动」，说明旧答案、建议的新答案和原因。
5. 过时的条目标「已停用」并写原因，不删除。
6. 不写客户个人信息。

## 交付
更新 `常见问题.md`（在计划里时写进本次产物目录），并在同一文件末尾列出本次改动：

```
# 常见问题

## <分类>
### 问：<客户的说法>
答：<结论>。<步骤>
适用：<条件>　依据：<老板规则 / 日期>　来源：<工单编号>　更新：<日期>

## 本次改动
| 条目 | 新增 / 修改 / 停用 | 原因 | 来源工单 |

## 待你确认的改动
- …
```

## 使用边界

优先使用已有信息；用户的数量、格式和任务范围优先于本文默认模板。工具权限、主目录/附加只读、Plan 模式与预算以当次实际能力为准；不换工具规避拒绝。这里只给工作方法，不授权写入、命令、付费、发送、提交或发布；未执行/验证的步骤如实标明。
